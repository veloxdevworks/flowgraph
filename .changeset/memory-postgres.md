Durable scoped memory on Postgres. `openPostgresBackend(url | { connectionString, pool, schema })` returns the checkpointer and a memory backend over one connection pool, in one schema. Checkpointer setup and memory migrations run under a per-schema advisory lock (on a dedicated connection), so any number of hosts can start together on a fresh database or schema; migrations are forward-only and transactional; a schema migrated by a newer flowgraph is refused. Writes take advisory locks on their scope and op id and read rows `FOR UPDATE`, so increments, appends, compare-and-set, the per-type subject cap and op-id dedupe are atomic across hosts. Memory transactions run at `READ COMMITTED` regardless of the database default. A pool `openPostgresBackend` creates reports idle-connection errors (e.g. a terminated backend) through `onPoolError` instead of crashing the process. Also exports `createPostgresMemoryBackend`, `migratePostgresMemorySchema` and `maybeSweepPostgres`. Adds a `pg` dependency.
