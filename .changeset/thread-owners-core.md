**Breaking:** `run()` and `stream()` refuse input that sets any key starting with `__` with `RESERVED_CHANNEL_BLOCKED`, policy or not; that prefix is reserved for engine bookkeeping (`__services`, `__worktrees`, `__agentReplay`, `__once`, `__mapCollect`, `__mapTask`, `__issues`, `__interrupt__`, and any channel added later) and was never meant as input. Under a node policy, graphs may not declare or write `__` channels or name them in a subgraph `stateMap.in` / `stateMap.out` (`RESERVED_CHANNEL_BLOCKED`), `runtime.services.rehydrateOnResume` and `runtime.worktrees.cleanupOnEnd` are refused when the policy blocks `service` / `worktree` nodes or host programs (`HOST_EXEC_BLOCKED`), saved service entries are not restarted and saved worktrees are not removed for such a graph, and a `hitl` review `diff` that runs `git diff` is refused under `blockHostExec` (a review with no `diff` skips the workspace diff instead). An embedded subgraph no longer hands any `__` channel back to its parent, so a parent does not see the child's `__services` or `__worktrees` (stop the child's services and remove its worktrees inside the child). Saved agent replay entries are loaded only for the thread being resumed: `hydrateReplayFromInterruptPayload(payload, threadId)` now takes the thread id and ignores payloads without `__nodeId`. Under a node policy, a node or hook can no longer write an engine channel it does not own (other nodes' writes to `__services`, `__worktrees`, `__issues` and the like are dropped), and interrupt data a graph passes to `ctx.interrupt` loses its `__` keys. New helpers: `assertGraphRuntimeAllowed`, `assertNoReservedChannels`, `assertNoReservedInput`, `isReservedChannel`, `reservedStateMapRefs`, `RESERVED_CHANNEL_PREFIX`, `hydrateThreadReplay`, `replayKeyBelongsTo`, `hostExecAllowed`, `collectNodeWriteChannels`.

New `ThreadOwnerRegistry` interface (`claim`, first claimant of a thread id owns it; `get`) with `createInMemoryThreadOwnerRegistry`. The node policy gains `allowedTools` (agent function tools and builtins mapped onto them, `TOOL_BLOCKED`), `allowedFunctions` (`function` / `code` nodes, `FUNCTION_BLOCKED`) and `blockHostExec` (workshop `git diff`, `HOST_EXEC_BLOCKED`), checked when the graph is built and again when it runs; the service tools refuse to start, stop or restart anything when the policy blocks `service` nodes. `guardedFetch` stops at `maxResponseBytes` (default 10 MiB, `OUTBOUND_RESPONSE_TOO_LARGE`) and `timeoutMs` (default 30 s, `OUTBOUND_TIMEOUT`). The policy also gains `blockAgentRefs` (`with.agent`, `AGENT_REF_BLOCKED`), `blockImports` (graph `imports` in inline subgraphs and `map` inners, `IMPORTS_BLOCKED`) and `blockInboundWebhooks` (`wait` `with.webhook` and `runtime.webhookServer`, `INBOUND_WEBHOOK_BLOCKED`), with `assertAgentRefAllowed`, `assertImportsAllowed` and `assertInboundWebhookAllowed`. Providers passed to `compileGraph` are scoped to that graph and the subgraphs it embeds; a graph compiled with a node policy sees only those, and does not add them to the process-wide registry.
