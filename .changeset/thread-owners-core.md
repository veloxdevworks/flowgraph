"@flowgraph/core": minor

**Breaking:** `run()` and `stream()` refuse input that sets any key starting with `__` with `RESERVED_CHANNEL_BLOCKED`, policy or not; that prefix is reserved for engine bookkeeping (`__services`, `__worktrees`, `__agentReplay`, `__once`, `__mapCollect`, `__mapTask`, `__issues`, `__interrupt__`, and any channel added later) and was never meant as input. Under a node policy, graphs may not declare or write `__` channels or name them in a subgraph `stateMap.in` / `stateMap.out` (`RESERVED_CHANNEL_BLOCKED`), `runtime.services.rehydrateOnResume` and `runtime.worktrees.cleanupOnEnd` are refused when the policy blocks `service` / `worktree` nodes or host programs (`HOST_EXEC_BLOCKED`), saved service entries are not restarted and saved worktrees are not removed for such a graph, and a `hitl` review `diff` that runs `git diff` is refused under `blockHostExec` (a review with no `diff` skips the workspace diff instead). An embedded subgraph no longer hands any `__` channel back to its parent, so a parent does not see the child's `__services` or `__worktrees` (stop the child's services and remove its worktrees inside the child). Agent replay entries (the model turns and tool results an agent reuses when it re-runs after an interrupt) now belong to one execution of a compiled graph (one `run`, `resume` or `continueRun` call) instead of a process-wide cache. They travel with the LangGraph invoke config, so another thread, run or compiled graph can never see them; nodes inside an embedded subgraph or a map are keyed by the ids of the subgraph nodes above them plus their own id; a resume rebuilds them only from the snapshot the engine attached to its own thread's pending interrupts. Any node an agent calls as a tool (`tools: [{ node }]`) keeps its own entries, below the calling agent and numbered per tool call, and so does everything it runs: an agent, a `hitl` node, the nodes of a subgraph and of map items inside it, and node tools those call in turn. An interrupt at any depth saves the entries of the whole top-level node it runs under, and a resume accepts only entries below that node whose paths the engine itself produces, so nested node tools, different node tools and two calls to the same node in one turn each resume with their own model turns and the approved call is the one that runs. Each subgraph called as a tool also gets its own checkpoint namespace per call, so calling the same subgraph twice in one turn no longer resumes the first call's checkpoint for the second. A `map` node used as a node tool is refused with a clear error (it was never runnable as a tool). Cached tool results now record the tool name and a hash of the arguments; on resume a cached result is reused only for the same call, and a different call at that point fails the run with `ReplayMismatchError` (`code: "REPLAY_MISMATCH"`) instead of returning another call's result (results saved by an earlier release are reused as before). Threads interrupted by an earlier release resume with the entries that release saved (read only from the thread's own pending interrupts, for the top-level node that raised them), so tools approved before an upgrade are not run again. The exception is an agent inside a subgraph: an earlier release saved its entries under a key this release does not trust, so such an agent re-runs the tools it had already run once after the upgrade (as it would after a process restart before). The `__agentReplay` channel is no longer read or written (it stays declared so older checkpoints load). **Breaking:** for every graph, `state` in an expression (`{{ }}` templates and `when` conditions) leaves out `__` channels, however it is read (`state.__x`, `state['_' + '_x']`, `{{ state }}`, `keys(state)`). Under a node policy, a `{{ }}` read of a `__` channel in any node `with` field (prompts, messages, tool arguments) is refused (`RESERVED_CHANNEL_BLOCKED`), including indexes spelled with `\u005f` or `\_`, or built from constants with operators and the string functions `lower`, `upper`, `trim`, `slice`, `string`, `default` and `coalesce` (`state['_' + '_x']`, `state[('_' |> trim) + '_x']`) at any nesting depth; an index that calls another function (`replace`, `join`, ...) or is computed at run time (`state[input.k]`) is not followed, so this check is a diagnostic, and the hidden `state` view is what keeps such reads empty, and names that normalise to `__` (NFKC, format characters such as zero-width spaces removed, leading spaces ignored) count as reserved everywhere `isReservedChannel` is used. **Breaking:** the replay-cache exports `clearAllReplayCaches`, `clearThreadReplayCache`, `hydrateReplay`, `hydrateReplayFromInterruptPayload`, `snapshotReplay` and `replayCacheKey` are removed; custom nodes use `runScopeOf(ctx._lgConfig)`, `ReplayStore` and `replayNodeKey`. Nodes inside an embedded subgraph now report the parent run's `runId` and `threadId` in `ctx.meta` and `{{ run.* }}` (they were empty). **Breaking:** `__` keys are now removed, for every graph, from a node's rendered `input` (map inner nodes too), the input a `node:before` hook hands back, the arguments a model passes to a node used as an agent tool, a subgraph's child input (the child also no longer receives the parent's `__` channels, such as `__once`), the payload of a `node:before` hook's interrupt, and a map node's collected results (`collect.to` / `collect.map`). Input a `run:before` hook hands back is refused like run input. Under a node policy, a node `input` that sets a `__` key or reads a `__` channel (spelled any of the ways above) is refused (`RESERVED_CHANNEL_BLOCKED`). Under a node policy, a node or hook can no longer write an engine channel it does not own (other nodes' writes to `__services`, `__worktrees`, `__issues` and the like are dropped), and interrupt data a graph passes to `ctx.interrupt` loses its `__` keys. New helpers: `assertGraphRuntimeAllowed`, `assertNoReservedChannels`, `assertNoReservedInput`, `isReservedChannel`, `reservedStateMapRefs`, `RESERVED_CHANNEL_PREFIX`, `withoutReservedKeys`, `reservedInputRefs`, `reservedTemplateRefs`, `ReplayStore`, `ReplayMismatchError`, `replayNodeKey`, `runScopeOf`, `hostExecAllowed`, `collectNodeWriteChannels`.

New `ThreadOwnerRegistry` interface (`claim`, first claimant of a thread id owns it; `get`) with `createInMemoryThreadOwnerRegistry`. The node policy gains `allowedTools` (agent function tools and builtins mapped onto them, `TOOL_BLOCKED`), `allowedFunctions` (`function` / `code` nodes, `FUNCTION_BLOCKED`) and `blockHostExec` (workshop `git diff`, `HOST_EXEC_BLOCKED`), checked when the graph is built and again when it runs; the service tools refuse to start, stop or restart anything when the policy blocks `service` nodes. `guardedFetch` stops at `maxResponseBytes` (default 10 MiB, `OUTBOUND_RESPONSE_TOO_LARGE`) and `timeoutMs` (default 30 s, `OUTBOUND_TIMEOUT`). The policy also gains `blockAgentRefs` (`with.agent`, `AGENT_REF_BLOCKED`), `blockImports` (graph `imports` in inline subgraphs and `map` inners, `IMPORTS_BLOCKED`) and `blockInboundWebhooks` (`wait` `with.webhook` and `runtime.webhookServer`, `INBOUND_WEBHOOK_BLOCKED`), with `assertAgentRefAllowed`, `assertImportsAllowed` and `assertInboundWebhookAllowed`. Providers passed to `compileGraph` are scoped to that graph and the subgraphs it embeds; a graph compiled with a node policy sees only those, and does not add them to the process-wide registry.
