Graph store failures no longer send the file-system error to clients. A failed write of a thread's graph or meta file (disk full, permissions, an I/O error) answers `503 GRAPH_STORE_WRITE_FAILED`, and a stored graph file that exists but cannot be read answers `503 GRAPH_STORE_READ_FAILED` instead of looking like a missing graph. Both messages name only the thread; the path, errno and stack are logged (`graph store write failed` / `graph store read failed`). Any other failed system call that reaches REST, `/invocations`, the request handler or a connect command answers `500 INTERNAL_ERROR` with no detail, which is logged. Run events (`run.error`, `node.error` and other error events, over SSE, `/invocations` streams, connect and the event journal) whose error is a system error say `Internal server error (error id err_…)` and carry that `errorId`; the log line with the same id has the text. Errors from a graph's own nodes keep their message. A graph store path that is not a directory (`ENOTDIR`) is now a read failure for the graph file as it already was for the meta file. Other errors keep their messages and statuses. `GraphStoreError` is exported.
