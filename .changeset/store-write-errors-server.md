Graph store failures no longer send the file-system error to clients. A failed write of a thread's graph or meta file (disk full, permissions, an I/O error) answers `503 GRAPH_STORE_WRITE_FAILED`, and a stored graph file that exists but cannot be read answers `503 GRAPH_STORE_READ_FAILED` instead of looking like a missing graph. Both messages name only the thread; the path, errno and stack are logged (`graph store write failed` / `graph store read failed`). Any other failed system call that reaches REST, `/invocations`, the request handler or a connect command answers `500 INTERNAL_ERROR` with no detail, which is logged. System error text (an errno code in Node's message format) no longer reaches clients from a run: it is masked as `Internal server error (error id err_…)` in failure events (`run.error`, `run.aborted`, `run.issue`, `node.error`, `node.retry`, `hook.error`, `skill.error`, in any field), in issues inside `node.end`, `state.update`, `run.end`, `run.paused` and `memory.recall` block errors, and in the issues and state the server returns. A masked event carries `errorId`; the id is a keyed HMAC of the thread and the text (`FLOWGRAPH_ERROR_ID_KEY` / `errorIdKey`, else a random key per process), so the same text in a thread has the same id everywhere and cannot be guessed back from it, and each process logs the id once as `run.event.error` with the text. The check is linear in the length of a string. Errors from a graph's own nodes keep their message. A graph store path that is not a directory (`ENOTDIR`) is now a read failure for the graph file as it already was for the meta file. Other errors keep their messages and statuses. `GraphStoreError` is exported.
