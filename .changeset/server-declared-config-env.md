The server expands `${VAR}` in uploaded graphs by the same rule as `loadGraph`. A trusted author's upload is parsed first, then expanded only in `config` and `runtime` (each inline subgraph's against its own list) and only for names the graph lists under `secrets:`. Any other name in `config` or `runtime` is refused as `SECRET_UNDECLARED`, placeholders elsewhere (node bodies, prompts, `metadata`) stay literal and are never read, and `$${X}` stays the literal `${X}`. The graph store, the session and `GET /runs/:id` keep the YAML as uploaded, and `parseGraphYaml` returns that text whenever it expanded anything. In the diagnostics and errors (message, stack and cause) that uploads, preflight and compiling a graph return, an expanded value is replaced with `[REDACTED]` wherever it is quoted or is the whole message, and, at 8 or more characters, anywhere else; diagnostic paths are left as they are. The untrusted upload check finds `${VAR}` in parsed strings as well as in the raw text, so a placeholder written with a YAML escape such as `"\u0024{X}"` is refused too. `@flowgraph/core` exports `expandGraphEnv` (which now also reports the host values it substituted and the strings they went into), `MIN_REDACTED_CONFIG_VALUE` and `recordGraphEnvExpansion` for hosts that parse YAML themselves.

**Breaking for `token` mode:** callers holding `FLOWGRAPH_AUTH_TOKEN`, and `/invocations` callers on an AgentCore Runtime (`FLOWGRAPH_AGENTCORE=1`) in `token` mode, are untrusted authors by default, so their uploads get the untrusted upload policy (no `shell`, `script` or `service` nodes, no `${VAR}` or `secret.*`, public-only `http` and `webhook`). Set `FLOWGRAPH_TRUST_TOKEN_CALLERS=1` (`trustTokenCallers: true` in `ServerConfig`) to make them trusted; the server logs a warning at startup when it is on. OIDC trust (trusted roles and teams) and `none` mode are unchanged. An embedded `RunService` whose config sets none of `auth`, `authToken` and `agentcore` stays trusted for its own in-process calls.

**Migration:**
- A `token`-mode server (including a placement worker reached with a shared token, or an AgentCore Runtime serving `/invocations`) that runs uploads with `shell`, `script` or `service` nodes: set `FLOWGRAPH_TRUST_TOKEN_CALLERS=1` if every caller that reaches it may run host commands on it, or move those authors to `oidc` with a trusted role or team. Stored graphs that use those nodes are refused on their next run until you do.
- A graph that needs a host value outside `config` / `runtime`: put it in `config.vars` (with the name under `secrets:`), run input, or `{{ secret.NAME }}`.
- A graph whose `config` / `runtime` uses an undeclared `${VAR}`: add the name to `secrets:`.
