Per-caller identity with OIDC. Set `FLOWGRAPH_OIDC_ISSUER` and `FLOWGRAPH_OIDC_AUDIENCE` and every REST, SSE, AgentCore `/invocations` and connect request must carry a JWT from that issuer (discovery, cached JWKS with rotation, RS256/ES256 by default, `exp`/`nbf`/`iat` with `FLOWGRAPH_OIDC_CLOCK_SKEW_SECONDS`, `aud`/`iss`; claim names configurable). Each caller is then its own principal: a thread belongs to whoever started it (403 `THREAD_NOT_OWNED` for anyone else, `GET /runs` lists only your own), memory is written as and resumable only by that caller, and a graph name belongs to the first caller in an org to upload it (409 `GRAPH_NAME_TAKEN`, kept in the sqlite/postgres memory database). Graphs from callers outside `FLOWGRAPH_OIDC_TRUSTED_ROLES` / `FLOWGRAPH_OIDC_TRUSTED_TEAMS` cannot use shell, script, service, worktree, skill or demo nodes, file subgraphs, `${VAR}` or `secrets.*`, host paths, or provider endpoint and key overrides (403 `UPLOAD_*`, checked at upload and again at run). Auth failures are `{ error, code }` with `AUTH_REQUIRED`, `AUTH_INVALID_TOKEN`, `AUTH_TOKEN_EXPIRED`, `AUTH_NO_ORG` or `AUTH_PROVIDER_UNAVAILABLE`. New `FLOWGRAPH_SETUP_LOCK_TIMEOUT_MS`.

**Breaking:** `FLOWGRAPH_AUTH_TOKEN` is now a single-user mode; on a server with `DATABASE_URL` or a durable `FLOWGRAPH_MEMORY_BACKEND` it starts only with `FLOWGRAPH_AUTH_MODE=token`. `FLOWGRAPH_AUTH_DISABLED=1` on such a server refuses to start unless `FLOWGRAPH_INSECURE_DEV=1`, and without that flag its callers are untrusted authors. Reusing a thread id for a different graph is a 409 `THREAD_ID_CONFLICT`. The `flowgraph` CLI is unaffected.
